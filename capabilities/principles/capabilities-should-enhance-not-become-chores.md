## What it does

Keeps the capabilities framework focused on speed and clarity. A capability
should help an agent find or execute useful work faster than rediscovery would.

## When to reach for it

Use this when a capability proposal, template, or evidence rule starts feeling
heavier than the work it supports.

## How to use it

1. Start with the smallest useful card: what this helps with, when to reach for
   it, how to use it, and what it depends on.
2. Leave speculative or half-shaped material in `kitchen/`.
3. Add evidence counters, ledger events, or watch fields only when the card is
   reused, risky, depended on, or promoted.
4. If maintaining a card costs more than rediscovering the fact, simplify it or
   deprecate it.
5. Prefer one clear capability that changes behavior over a broad note that
   future agents will ignore.

## What it depends on

None.

## Failure modes

- Treating every note as governed makes the framework feel like paperwork.
- Treating every idea as proven creates false certainty.
- Keeping stale cards because they once sounded useful makes the index noisy.
