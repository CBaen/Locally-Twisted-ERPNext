## Probe 1 — Fanfaire SWAP mechanic

**What the source actually says:** The Fanfaire design-studio page describes SWAP as: "Let clients swap elements (e.g., iridescent shimmer wall for gold)." The actor is the client — so SWAP is customer-facing. The customer, viewing a decorator-prepared design proposal, presses SWAP to substitute one element for an alternative that the decorator has pre-paired.

**Honest assessment:** My "inversion" framing was imprecise. Fanfaire's SWAP is customer-facing, same as my ghost placeholder — both let the customer make a substitution. What's different is the *trigger*: Fanfaire requires the decorator to pre-pair alternatives; my ghost is structurally generated by completion (color the arch → ghost column appears). So the "inspiration" connection is real but the "inversion" description is misleading. The cascading unlock is genuinely my own design move, not a flip of an existing pattern.

On the second part of the probe — does research support cascading over showing all ghosts at once? Fetched NN/G's progressive disclosure article. It distinguishes "progressive disclosure" (secondary items available on request) from "staged disclosure" (sequential unlock). The key cognitive argument is attention prioritization: "the very fact that something appears on the initial display tells users that it's important." Showing all ghosts at once competes with the colored piece for attention; the single ghost focuses it. NN/G doesn't name completion-momentum as a benefit, so I won't claim that. But the attention-prioritization argument does support showing one ghost at a time over several.

**Changes made:** Reframed Q5 in REASONING.md. "Inverting SWAP" replaced with "inspired by the concept of customer-initiated element substitution (Fanfaire)." Added explicit argument for cascading over all-at-once using NN/G's progressive disclosure attention-prioritization principle. Noted the cascade is my design judgment, not a researched pattern per se.
